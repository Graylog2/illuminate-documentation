Group Fields

Overview

The group fields describe logical group constructs used to organize identities, accounts, or principals within an operating system, directory service, or application platform.
Groups are commonly used to assign permissions, privileges, or access policies to multiple members collectively.
This entity provides a normalized representation of group identifiers, names, membership relationships, and contextual attributes.

Design and Usage

The group entity models group objects independently of the specific identity system or directory implementation.
It supports representation of both local and directory-based groups and their relationships to member identities.
Fields within this entity enable correlation between group membership changes, access evaluations, and privilege assignments across heterogeneous systems.

Common Use Cases

  • Tracking group membership and membership changes for auditing and compliance purposes.
  • Identifying privileged or sensitive groups associated with elevated access.
  • Correlating authentication or authorization events with group-based access controls.
  • Normalizing group identifiers across operating systems, directory services, and cloud identity platforms.

Implementation Notes

As a top-level entity, group represents the group object itself rather than the event that references it.
Group identifiers may be numeric, string-based, or security identifiers depending on the source system.
Membership-related fields should be populated when group membership is explicitly observed or modified.
If group context is implied but not explicitly provided, corresponding group fields should be included to maintain relational integrity and clarify access semantics.
