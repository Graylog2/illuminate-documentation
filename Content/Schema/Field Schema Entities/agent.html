Agent Fields

Overview

The agent entity represents the software that collects and ships an event into Graylog - such as Graylog's own collector, Beats, or Fluentd - as distinct from the subject of the event itself. The same fields apply more broadly to other kinds of software agents as well, such as EDR/AV clients or management agents (e.g. SCCM), provided the agent in question is the thing responsible for producing or shipping the event rather than the event's subject.

Design and Usage

Fields describe the identity of the collecting/shipping agent only - never the subject of the event being described. For example, on an event describing an EDR product's own status change, agent_* fields identify the software that shipped that event into Graylog, not the EDR product itself; the EDR product's own identity is carried by other fields (such as event_source_product or vendor_* fields).

This entity also carries a small set of fields specific to Graylog's own collector architecture (fleet and source-routing identifiers, and receiver type).

Common Use Cases

  • Identifying which collector, and which specific installation of that collector, shipped a given event
  • Associating an event with the managed fleet a collector instance belongs to
  • Associating a collected event with the specific source or receiver configuration within a collector that produced it
  • Distinguishing between multiple instances of the same agent software running across an environment, whether that agent is a log collector or another kind of on-host agent

Implementation Notes

As a top-level entity, agent defines a coherent object representing a single collecting/shipping agent instance. Its fields should be included whenever the software responsible for collecting or shipping an event needs to be identified, independent of whatever entity fields describe the event's actual subject matter.

field field_type description example_values

agent_build_original

keyword

Extended build information for the agent, in whatever format the source provides (build hash, packaging metadata, etc.).

agent_ephemeral_id

keyword

Ephemeral identifier of the agent. Unlike agent_id, this value changes across restarts of the same agent installation.

agent_fleet_id

keyword

Unique identifier of the managed fleet/group this agent instance is assigned to.

agent_id

keyword

Unique identifier of the agent that collected, shipped, or observed this event (e.g. a Beat's UUID or a custom collector's instance GUID). Persists across restarts of the same agent installation.

agent_name

keyword

Custom, human-readable name assigned to the agent instance. Useful for distinguishing between multiple instances of the same agent type running in an environment.

agent_receiver_type

keyword/lowercase

Type of receiver/input mechanism that collected this specific event within the agent, as reported by the Graylog Collector (e.g. file_log). For other agent types, this maps to the equivalent underlying concept, such as an OpenTelemetry Collector receiver name.

file_log

agent_source_id

keyword

Identifier associating this agent with a source in Graylog Server's architecture (e.g. a Graylog Input ID). This field is generated by the Graylog Collector; other agent types should only populate this field in situations where the Graylog Collector is not being used to collect the logs in question.
